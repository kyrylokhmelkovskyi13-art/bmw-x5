# Анализ исходной модели BMW X5 E53

Отчёт автоматически создан GitHub Actions из `bmw-x5.glb`.
Полные машинные данные: [`build/model_report.json`](../build/model_report.json).

## Подтверждённая структура GLB

| Показатель | Результат |
|---|---:|
| Узлы (nodes) | 103 |
| Меши (meshes) | 101 |
| Материалы | 98 |
| Встроенные изображения | 19 |
| Корневые узлы сцены | 1 |

В сцене один корневой узел `Sketchfab_model`. Его дочерний узел
`x5.obj.cleaner.materialmerger.gles` содержит 101 дочерний объект.

## Ограничения исходной иерархии

Меши и узлы имеют автоматические имена `Object_0` … `Object_102`.
В отчёте нет отдельных именованных узлов для:
- кузова/рамы;
- передней и задней оси;
- четырёх колёс;
- рулевого механизма;
- подвески.

Это не доказывает, что геометрия колёс отсутствует: она может быть частью
объектов с общими именами. Но автоматически назначить правильные вращающиеся
колёса и синхронизацию руля по текущим именам нельзя.

## Материалы стекла

В GLB есть материалы с режимом прозрачности `BLEND`, в том числе:
- `Hl_glass`;
- `wind_glass5`;
- `Material__109`;
- `Material__148`;
- `Material__217`;
- `Material__218`;
- `Material__41`.

Режим `BLEND` подтверждает наличие прозрачного смешивания в исходном GLB,
но не гарантирует, что стекло будет бесцветным/прозрачным после переноса в MudRunner.
Потребуется отдельная настройка материалов и проверка в игре.

## Следующие технические задачи

1. Разделить геометрию на кузов, колёса и отдельные подвижные элементы.
2. Назначить оси вращения колёс и рулевую связь.
3. Создать физические кадры шасси и подвески.
4. Подготовить экспортируемую модель и материалы для оригинального MudRunner.
5. Создать Truck class через MudRunner Editor и проверить загрузку/управление.

**Вывод:** исходная модель достаточно богата геометрией и материалами для дальнейшей
подготовки, но её текущая GLB-иерархия не содержит достоверных имён физических частей.
Готовый игровой мод и корректную физику по одному этому отчёту подтвердить нельзя.
