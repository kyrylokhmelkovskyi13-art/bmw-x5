# BMW X5 E53 — оригинальный MudRunner

## Статус
Это подготовка исходного проекта под **оригинальный MudRunner**, не SnowRunner.
Исходная модель в репозитории — `bmw-x5.glb`. Для игрового truck mesh её необходимо
конвертировать в поддерживаемый игрой формат и проверить в MudRunner Editor.

## Структура будущего мода
- `classes/trucks/bmw_x5.xml` — класс машины и физика.
- `meshes/trucks/bmw_x5.x` — экспортированная модель.
- `meshes/trucks/bmw_x5.xml` — mesh/material mapping.
- `strings.xml` — название машины.

## Что уже подготовлено
- Название машины: BMW X5 E53.
- Исходная модель и текстуры сохранены в корне репозитория.
- `tools/inspect_glb.py` извлекает имена узлов/мешей/материалов и встроенные изображения из GLB.
- `tools/blender_prepare.py` импортирует GLB в Blender, делает геометрический отчёт и OBJ/MTL-файлы для осмотра.
- GitHub Actions автоматически запускает подготовку геометрии; последний запуск завершился успешно: [workflow #7](https://github.com/kyrylokhmelkovskyi13-art/bmw-x5/actions/runs/44528068107).

## Результаты геометрической проверки
Автоматический анализ Blender обработал 101 mesh-объект исходного GLB.
Выделены четыре сильных кандидата на колёса: `Object_98`, `Object_99`,
`Object_100`, `Object_101`. Их bounding box примерно
`0.364 × 0.890 × 0.890` единицы модели; оценка радиуса по геометрии — около
`0.445` единицы. Это измерения исходной модели, а не готовые параметры подвески.

Последний расширенный экспорт выделил 41 объект в широкой зоне салона/приборной панели.
Это только геометрический shortlist для визуальной проверки, а не подтверждённый список
деталей интерьера. В частности, руль пока не идентифицирован достоверно.

В модели нет осмысленных имён узлов для руля, осей и подвески: используются
имена вида `Object_XX`. Поэтому автоматический поиск по имени не позволяет
надёжно назначить steering wheel. Найденный объект нельзя считать рулём,
пока его форма и положение не подтверждены.

## Почему пока нет готового truck XML
Физический XML должен ссылаться на реальные кадры кузова, шасси и четырёх колёс.
Эти имена нельзя достоверно вывести из списка файлов репозитория. Если вписать
придуманные имена, машина не будет корректно загружаться или управляться.

## Следующий обязательный шаг
Открыть модель в совместимом 3D-редакторе, определить реальные части кузова/салона,
подготовить отдельные физические кадры и экспортировать модель в формат, который
принимает редактор оригинального MudRunner. Затем через MudRunner Editor создать
Truck class и назначить реальные кадры/колёса.

## Найденный путь экспорта в .X
Найдена отдельная Blender-надстройка [io_scene_mudrunner](https://github.com/fred-rum/io_scene_mudrunner),
которая заявлена как экспортёр DirectX для Spintires: MudRunner. По её README она
рассчитана на Blender 2.78 и старше/совместимые версии; это не означает, что она
проверена на нашей BMW или на грузовиках с такой структурой.

Официальное руководство MudRunner требует единственный корневой объект, ориентацию
грузовика вдоль X, физические объекты с collision-моделями и корректные кадры
иерархии. Оно описывает экспорт через 3ds Max 2012 и kW X-port. Поэтому следующий
технический эксперимент — проверить старый MudRunner-экспортёр на импортированной
геометрии BMW и затем открыть результат в MudRunner Editor. Сам факт создания .X
не будет считаться подтверждением совместимости.

Источники:
- [Официальное руководство MudRunner (PDF)](https://cdn.focus-home.com/admin/games/mudrunner/docs/ModdingGuide_Mudrunner.pdf)
- [io_scene_mudrunner — Blender exporter](https://github.com/fred-rum/io_scene_mudrunner)
- [Описание ограничений экспортёра и его применения](https://www.mudrunnermods.com/spintires-mudrunner-map-making-big-book/#mudrunner-exporter-for-blender)

## Пробный экспорт DirectX .X
Добавлен автоматический эксперимент:
- `tools/export_mudrunner_x.py` импортирует OBJ в Blender 2.78 и вызывает экспортёр MudRunner;
- экспорт выполняется с `FlattenType=scale` как экспериментом для сохранения иерархии/трансформаций кадров;
- `tools/validate_x_export.py` проверяет заголовок DirectX и считает блоки Frame/Mesh/Material/Normals/UV;
- workflow `.github/workflows/test-mudrunner-x.yml` сохраняет .X и отчёт в GitHub Actions artifacts.

Это только структурная проверка текстового .X. Она не подтверждает корректность координат, collision, физики, материалов или загрузку в MudRunner Editor.

**Не считать этот репозиторий готовым игровым модом до успешной проверки в игре.**

## Дополнительный замер геометрии колёс

Добавлен `tools/analyze_wheel_layout.py`. Он повторно использует измерения четырёх кандидатов из `geometry_inventory.json` и рассчитывает расстояние между центрами колёс по двум исходным координатным осям. Workflow `prepare-geometry` теперь сохраняет `wheel_layout_report.json` вместе с остальными артефактами.

Отчёт предназначен для проверки геометрии исходной GLB/OBJ-модели. Он не задаёт оси MudRunner, не создаёт физические кадры и не является готовыми параметрами подвески. Перед переносом размеров в Truck XML нужно подтвердить ориентацию и масштаб в MudRunner Editor.


## Проверка иерархии pivot-кадров

Валидатор дополнен разбором вложенности блоков `.X`: он проверяет не только наличие
четырёх pivot-кадров, но и то, что кандидаты колёс вложены в ожидаемые кадры:
- `Object_98` → `wheel_pivot_end_a_side_a`
- `Object_101` → `wheel_pivot_end_a_side_b`
- `Object_99` → `wheel_pivot_end_b_side_a`
- `Object_100` → `wheel_pivot_end_b_side_b`

Это проверка структуры файла, а не проверка правильности ориентации осей, положения
pivot относительно ступицы или поведения подвески/рулевого управления в игре.

## Подготовка к проверке у друга (без покупки игры разработчиком)

Для ручной подготовки проекта не требуется устанавливать MudRunner на компьютере автора мода.
Нужен один небольшой оригинальный файл из установленной игры у тестировщика:

`Media.zip/classes/trucks/uaz469.xml`

Его можно извлечь из `Media.zip` любым архиватором (например, 7-Zip) и передать отдельно.
Путь к `uaz469.xml` как к базовому примеру для ручного создания модов описан в
[руководстве сообщества по моддингу MudRunner](https://steamcommunity.com/sharedfiles/filedetails/?id=1187757690).
Это не заменяет проверку в MudRunner Editor: официальный гайд описывает создание нового truck XML
через команду **New truck...** в редакторе
(см. [официальное руководство](https://cdn.focus-home.com/admin/games/mudrunner/docs/ModdingGuide_Mudrunner.pdf)).

После получения файла можно сверить реальные имена секций и ссылок на классы/кадры.
Нельзя просто переименовать UAZ в BMW: XML станет только отправной точкой, а геометрия,
колёса, кадры шасси, collision и подвеска должны соответствовать нашей модели.
